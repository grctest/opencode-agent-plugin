# Audit 06 — Vector / RAG / Embedding Pipeline

**Current grade: D · Target grade: A−**

The semantic layer is the project's differentiator ("no LLM domain detection — real embeddings"), and it is quietly broken at its mathematical foundation. Every feature built on it — room composition, reflection targeting, vector search, RAG context — inherits the defect.

## Issues

### V1 — Wrong pooling scheme + no encoder metadata (critical)
`src/services/model-manager.js:234-242`: mean pooling over token embeddings is hardcoded, and the attention mask is ignored (padding tokens contribute to the average). Snowflake arctic-embed models specify **CLS pooling** plus model-specific query-side prefixes per their model cards. Beyond pooling, the pipeline has no concept of encoder metadata: query prefixes are never injected, `token_type_ids` is always created (some models don't need it), output tensor selection is fragile, and there is no auto-detection from model config. Every embedding produced is systematically off-spec for non-mean-pooling models, and bringing a new model requires reading the source code. Nothing errors — retrieval quality is just degraded everywhere, permanently, invisibly. See full analysis in "Proposed fixes → V1 (rewritten)" below.

### V2 — Chunker loses content silently (major)
`src/services/vector-index.js:126-142`: `#chunkText` never splits a paragraph larger than `maxChunkSize` (oversized paragraph = one oversized chunk) and guesses `chars ≈ tokens×4` with a warn-only signal. Oversize chunks are then silently token-truncated at embed time (`model-manager.js:203-205`) — permanent, silent content loss in the RAG index.

### V3 — Embedder init races and dimension drift (major)
`src/services/embedding-service.js:28-48`: `initializeEmbedder` returns whatever init is in flight *even for a different requested model*; `ensureEmbedderInitialized` no-ops whenever any model is loaded. If a user configures a different embedding model than the one already loaded (or the default loaded at startup), they silently get the wrong one; per-dimension vec tables just orphan old data with no warning.

### V4 — Startup ignores configured embedding model (major)
`src/index.js:49` hardcodes `DEFAULT_EMBEDDING_MODEL/DEFAULT_EMBEDDING_QUANT` at plugin startup while `orchestrator.js:319-320` honors `config.embeddingModel/embeddingQuant`. The configured model is not what gets warm-loaded; first-use behavior depends on which path wins the race.

### V5 — Quiet fallback chain in persona search (major)
`composer.js:360-366` → precomputed-embedding search → `embedText` search → keyword match, each step silent; `searchPersonaEmbeddings` itself catches everything returning `[]` (`database.js:1227-1230`). Combined with the possibly-failing metadata filter (`database.js:1224`, see audit 03), selection can be running on tag-substring matching while everyone believes it's semantic.

### V6 — Drift detection removed but cost remains (minor)
README admits semantic drift detection was "removed" yet round contributions are still chunked and embedded every round. Either the feature decision should be revisited later or the pipeline should be simplified; today it's all cost, no benefit beyond generic RAG.

## Proposed fixes

### V1 (rewritten) — Full ONNX text encoder support

The original V1 identified wrong pooling + missing query prefixes. This rewrite expands it to handle **all quirks unique to different text encoder architectures** so any ONNX sentence-transformers model works out of the box, not just the three bundled ones.

#### The problem space

ONNX text encoders are not interchangeable black boxes. Each model family has unique requirements across five dimensions:

| Dimension | What varies | Examples |
|-----------|-------------|----------|
| **Pooling strategy** | How per-token vectors collapse to one sentence vector | CLS, mean, max, mean_sqrt_len, weightedmean, lasttoken |
| **Query prefix** | String prepended to queries (not documents) for asymmetric retrieval | `"query: "`, `"Represent this sentence for searching relevant passages: "`, `"search_query: "` |
| **Tokenizer special tokens** | Whether tokenizer adds `[CLS]`/`[SEP]` automatically, padding side, max length | BERT adds `[CLS]`+`[SEP]`; GTE-Qwen needs left-padding; E5 needs `</s>` suffix |
| **Input tensor names** | Which tensors the ONNX graph expects | Most use `input_ids, attention_mask, token_type_ids`; some omit `token_type_ids` |
| **Output tensor name** | Which output contains token embeddings | `last_hidden_state` (most) or `token_embeddings` (some) |

Getting any of these wrong degrades retrieval silently — no errors, just worse search results.

#### The fix: metadata-driven embedding pipeline

**1. Extend `model.json` schema** (generated by `scripts/model.mjs` at download time):

```json
{
  "name": "Snowflake/snowflake-arctic-embed-xs",
  "dims": 384,
  "maxTokens": 512,
  "modelType": "bert",
  "quant": "onnx/model_int8.onnx",
  "pooling": "cls",
  "queryPrefix": "Represent this sentence for searching relevant passages: ",
  "documentPrefix": "",
  "inputTensorNames": ["input_ids", "attention_mask", "token_type_ids"],
  "outputTensorName": "last_hidden_state",
  "paddingSide": "right",
  "normalize": true
}
```

Fields:
- `pooling`: `"cls" | "mean" | "max" | "mean_sqrt_len" | "weightedmean" | "lasttoken"` — required
- `queryPrefix`: string prepended to query text only (empty string = none) — optional
- `documentPrefix`: string prepended to document text only (empty string = none) — optional
- `inputTensorNames`: array of tensor names the ONNX session expects — optional, defaults to `["input_ids", "attention_mask", "token_type_ids"]`
- `outputTensorName`: `"last_hidden_state"` or `"token_embeddings"` — optional, defaults to auto-detect
- `paddingSide`: `"right"` or `"left"` — optional, defaults to `"right"`
- `normalize`: whether to L2-normalize after pooling — optional, defaults to `true`

**2. Auto-detect from Hugging Face metadata** (in `scripts/model.mjs`):

The download script already fetches `config.json` and `tokenizer_config.json`. Extend `extractMetadata()` to also:

- Read `config.json` → `model_type` to infer pooling: `bert`/`roberta`/`mpnet` → `mean` (default), `nomic-ai/nomic-embed` → `mean`
- Read Hugging Face's `1_Pooling/config.json` if present (many models ship this) → `pooling_mode` field maps directly
- Read `tokenizer_config.json` → `padding_side` (left vs right), `model_max_length`
- Detect `token_type_ids` need from `config.json` → `type_vocab_size > 0` means yes
- Default `queryPrefix`/`documentPrefix` to empty; override from model card metadata if available

**3. Refactor `model-manager.js:embed()`** to be pooling-strategy-aware:

```
embed(session, tokenizer, text, modelMeta) → Float32Array
```

Where `modelMeta` comes from `model.json` and drives:

- **Tensor construction**: build only the input tensors listed in `inputTensorNames`; skip `token_type_ids` if not needed
- **Pooling dispatch**: switch on `modelMeta.pooling`:
  - `cls`: take `embeddingData[0..dims-1]` (first token), attention-mask-aware (exclude pad tokens from consideration)
  - `mean`: average all non-pad token embeddings using attention mask
  - `max`: element-wise max across non-pad tokens
  - `mean_sqrt_len`: mean pooling divided by `sqrt(seq_len)`
  - `weightedmean`: position-weighted mean (position index as weight)
  - `lasttoken`: take last non-pad token (requires correct `paddingSide`)
- **Output tensor selection**: try `modelMeta.outputTensorName` first, fall back to `last_hidden_state || token_embeddings`
- **Normalization**: skip L2 norm if `modelMeta.normalize === false`

**4. Prefix injection in `embedding-service.js`**:

`embedText(text)` becomes `embedText(text, isQuery = false)`:
- If `isQuery` and `modelMeta.queryPrefix` is non-empty, prepend prefix to text before tokenization
- If `!isQuery` and `modelMeta.documentPrefix` is non-empty, prepend prefix
- Callers that embed queries (persona search, drift detection) pass `isQuery: true`
- Callers that embed documents (round summaries, contributions) pass `isQuery: false` (default)

**5. Update `scripts/model.mjs` download flow**:

After downloading `config.json`, fetch `1_Pooling/config.json` from the same Hugging Face repo (404 = not found, use defaults). Map its `pooling_mode` to our enum:

| HF `pooling_mode` | Our `pooling` field |
|--------------------|---------------------|
| `cls` | `"cls"` |
| `mean` | `"mean"` |
| `max` | `"max"` |
| `mean_sqrt_len_tokens` | `"mean_sqrt_len"` |
| `weightedmean` | `"weightedmean"` |
| `lasttoken` | `"lasttoken"` |

Also detect query/document prefixes from the model card's `sentence_transformers` config if present (some models embed `prompts` dict there).

**6. Validation on load** (`model-manager.js:loadModel()`):

- Warn if `pooling` field is missing from `model.json` (legacy model, assume `mean` as safe default)
- Warn if `inputTensorNames` are missing (use standard BERT names as fallback)
- On first embed, log the pooling strategy and prefix at info level for debuggability

#### Implementation scope

- **Lines changed**: ~80 in `model-manager.js` (embed refactor), ~20 in `embedding-service.js` (prefix injection), ~40 in `scripts/model.mjs` (auto-detection), ~10 in `model.json` schema
- **New code**: pooling dispatch switch (~40 lines), prefix logic (~10 lines), auto-detect fetch (~20 lines)
- **No new dependencies**: uses existing `@huggingface/tokenizers` and `onnxruntime-node`
- **Backward compatible**: existing `model.json` without new fields defaults to mean pooling, no prefix, standard BERT tensors — old models keep working

### V2 — Chunker loses content silently (unchanged)

`src/services/vector-index.js:126-142`: `#chunkText` never splits a paragraph larger than `maxChunkSize` (oversized paragraph = one oversized chunk) and guesses `chars ≈ tokens×4` with a warn-only signal. Oversize chunks are then silently token-truncated at embed time (`model-manager.js:203-205`) — permanent, silent content loss in the RAG index.

Fix: hard-split oversized paragraphs by sentence boundaries; use the already-bundled tokenizer (`@huggingface/tokenizers`) to size chunks in real tokens instead of the ×4 guess.

### V3 — Embedder init races and dimension drift (unchanged)

`src/services/embedding-service.js:28-48`: `initializeEmbedder` returns whatever init is in flight *even for a different requested model*; `ensureEmbedderInitialized` no-ops whenever any model is loaded. If a user configures a different embedding model than the one already loaded (or the default loaded at startup), they silently get the wrong one; per-dimension vec tables just orphan old data with no warning.

Fix: cache in-flight init per `(model, quant)`; `ensureEmbedderInitialized(model)` must reject a mismatched already-loaded model loudly (warn + reload) rather than no-op. On dim mismatch vs stored vectors, log an error naming the affected tables and refuse to mix (offer reindex).

### V4 — Startup ignores configured embedding model (unchanged)

`index.js:49` hardcodes `DEFAULT_EMBEDDING_MODEL/DEFAULT_EMBEDDING_QUANT` at plugin startup while `orchestrator.js:319-320` honors `config.embeddingModel/embeddingQuant`. The configured model is not what gets warm-loaded; first-use behavior depends on which path wins the race.

Fix: `index.js` reads `getConfig().embeddingModel ?? DEFAULT` once and passes it down; orchestrator consumes the same resolved value instead of re-resolving.

### V5 — Quiet fallback chain in persona search (unchanged)

`composer.js:360-366` → precomputed-embedding search → `embedText` search → keyword match, each step silent; `searchPersonaEmbeddings` itself catches everything returning `[]` (`database.js:1227-1230`). Combined with the possibly-failing metadata filter (`database.js:1224`, see audit 03), selection can be running on tag-substring matching while everyone believes it's semantic.

Fix: when the fallback chain steps down a level, emit one throttled warn naming the step (the logger's `warnThrottled` exists precisely for this); record `semantic_degraded=true` on the meeting row so the dashboard can show a banner.

### V6 — Drift detection removed but cost remains (unchanged)

README admits semantic drift detection was "removed" yet round contributions are still chunked and embedded every round. Either the feature decision should be revisited later or the pipeline should be simplified; today it's all cost, no benefit beyond generic RAG.

## Justification

V1 invalidates the core value proposition of embedding-based composition — everything downstream is tuning noise on a broken signal. The rewritten fix is still contained (metadata-driven pooling dispatch + download-time auto-detection), requires no new packages, and immediately improves retrieval, reflection targeting, and composition simultaneously. Critically, it makes the project genuinely extensible: users can bring any ONNX sentence-transformers model and get correct embeddings without code changes — just `npm run model:download -- --model=org/model-name` and the pipeline adapts.
